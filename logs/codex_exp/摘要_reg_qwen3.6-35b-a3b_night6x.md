## 失敗細節

- **T5 r2 第 1 次：假完成。** 模型被 `--deselect` 掉的那個測試（`test_report_benchmark.py::test_real_data_reconciles_and_matches_hand_calc`，要真實資料庫）吸引，花了很多步在它上面，最後在 `report_benchmark.py` 加了「資料庫不存在就回傳空 dict」的 2 行，回報「All 4 tests pass」。它跑的是 `tests/test_report_benchmark.py`，沒有看到 `tests/cio/test_daily.py` 的 2 個失敗（真正的 bug 在 `cio/daily.py`，r1、r3 都是改這裡）。派工的 `--check` 跑完整測試，抓到 2 failed，改動被還原。單一回合最久等了 1,580 秒（約 26 分鐘），output 41,438 token，context 峰值 59,665。這是回歸組第一次出現假完成；被規格測試擋下，不是假通過。
- **T5 r2 第 2 次：header 逾時（執行錯誤）。** 嘗試開頭的 task 93667 提示詞只有約 557 token（`n_tokens` 19,451 減掉生成的 18,894），想了約 20 分鐘後被取消；它不是主請求（主對話含系統提示和工具定義至少 6,000 token）。真正的主請求 task 93669 和它的重送（98436、103477）一直排在單一 slot 後面，沒有 `launch_slot_`，每 5 分鐘等不到 header 就被取消，最後整個嘗試判成 `provider.transport: Timed out waiting for response headers`，output 和步數都是 0。night3 H2 r1 也是同一型（見下面）。派工不會重試執行錯誤，這輪算失敗。（初版摘要寫成「主請求想了 20 分鐘」，2026-11-12 依 Fable 第四次審查更正。）
- **T4 r2：同一型，但剛好過了。** 開頭的 task 40827 提示詞約 519 token，想了 7,705 token（461 秒）；主請求排隊超過 5 分鐘被取消一次（task 40829），重送後才開始跑。這次嘗試 548 秒，另外兩輪是 187、211 秒。jsonl 的 `output_tokens`（651）和 `max_turn_wait`（181 秒）都沒有算進這個小請求。
- **T1 r1、r3**：同上，改動過大。

## 每次嘗試開頭的小請求（2026-11-12 補）

每次嘗試開頭，opencode 會平行送出一個提示詞約 500 token 的請求，主請求排在它後面。推測是產生 session 標題的請求（提示詞短、沒有工具定義、每次嘗試一個），server log 看不到內容，還沒確認。這一輪的統計（Fable 第四次審查重算）：

| 項目 | 數字 |
|---|---|
| 提示詞約 500 token 的請求數 | 19 個（20 次嘗試） |
| 生成時間合計 | 2,115 秒，佔整輪生成時間 10,366 秒的 20% |
| 生成 token 合計 | 35,934 |
| 每個的生成時間中位數 | 84 秒 |
| 超過 5 分鐘（會讓主請求 header 逾時） | 2 個：T5 r2 第 2 次（18,894 token，整次失敗）、T4 r2（7,705 token，重送後過） |

所以 header 逾時和題目難度無關，簡單題也會碰到；拉長 `headerTimeout` 能避免整次失敗，但這個小請求照樣佔掉約 20% 的生成時間。讓它不要思考或不要送比較直接，屬於 Codex總攬 的 `oc_llama.py`。jsonl 的 `output_tokens`、`max_turn_wait` 不含這個請求，估耗時組成要看 server log。

night3 H2 r1 回頭查過：當時跑了約 20 分鐘的 task 15334，提示詞約 580 token，也是這個小請求，不是主請求。

## 空轉

- 放寬後沒有出現「一直跑卻沒有進展」的空轉：最長的嘗試（T5 r2 第 1 次 3,712 秒、T5 r3 3,285 秒）每一步都有工具呼叫或輸出，停滯判定沒有觸發。

- 沒有碰到 context 上限（`exceed_context_size_error` 0 次）。

## 速度與資源

`--cache-ram 0` 下速度一樣沒有隨時間掉（`scripts/server_speed_ctx.py`）：開機 60 分鐘後、context <10k，生成 16.1 t/s、讀提示詞 93 t/s；context ≥30k 時生成 11.2 t/s。server log 裡沒有「making room for prompt cache entry」。

熱壓力全程 0。server footprint 2.4～3.8GB，壓縮記憶體最高 8.05GB（和 night5r 差不多）。可用記憶體最低 46%。swap 從 4,611MB 開始，開機 30～60 分鐘間最高約 7.8GB（+3.2GB，門檻 +6GB），之後回落，結束時 4,456MB。沒有觸發任何保護。開跑時 `ollama ps` 是空的。
